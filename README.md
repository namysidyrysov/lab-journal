# lab-journal

Редактор лабораторного журнала, который работает прямо в браузере. Ничего устанавливать не нужно.

Результат работы — обычная папка проекта: `journal.html` и `images/`. Журнал можно отправить другому архивом, и он откроет `journal.html` двойным кликом, без программы. Картинки в журнале увеличиваются по клику.

## Возможности

- Журнал — одна длинная страница из блоков: **эксперимент** и **текст** (например, для заключения).
- У эксперимента есть дата (день недели подставляется сам), список присутствовавших и колонки. По умолчанию есть четыре колонки: «Предпосылки», «Изменения в схеме», «Результаты», «Наблюдения и выводы».
- В каждой колонке отдельно **текстовое описание** и **область для картинок**. У картинки необязательная подпись: если она пуста, подписи в журнале нет.
- Эксперименты сами выстраиваются по дате, а номера считаются автоматически.
- **Автосохранение** и резервные копии: труд не пропадает.
- Оглавление выезжает по кнопке ☰ и закрывается после выбора пункта.
- Работает с любым числом проектов: один проект — одна папка.

## Требования

Браузер **Chrome или Edge**. Программе нужен доступ к папке на диске, а Firefox и Safari его не дают.

## Запуск

1. Скачайте репозиторий (Code → Download ZIP) или выполните `git clone`.
2. Откройте `index.html` в Chrome.
3. Нажмите «Открыть папку проекта» и выберите папку проекта. Chrome попросит разрешение на запись в неё.

Если в выбранной папке нет `journal.html`, программа предложит создать пустой журнал.

## Как пользоваться

**Эксперимент.** Кнопка «+ Эксперимент» сначала открывает окно с обязательными пунктами: дата (день пишется или выбирается, месяц и год выбираются, есть кнопка «Сегодня») и хотя бы один присутствовавший. Пока они не заполнены, эксперимент не создаётся. Изменить дату и участников позже можно по значку ✎ или ссылке «изменить» в заголовке.

**Присутствовавшие.** Фамилии отмечаются галочками. Новую фамилию можно добавить, а крестик убирает её из списка. В уже записанных экспериментах такая фамилия остаётся. Список хранится в самом журнале, в коде фамилий нет.

**Порядок и номера.** Эксперименты всегда стоят по дате. Номер считается по дням работы: 1, 2, 3… Если в один день несколько экспериментов, они получают номера 12.1, 12.2. Порядок внутри дня совпадает с порядком создания, его меняют кнопки ↑ ↓ (они работают только между экспериментами одного дня). Текстовые блоки остаются на своих местах.

**Колонки.** У каждой колонки при наведении есть кнопки ← → ✕, поэтому можно удалить любую колонку или поменять колонки местами. Кнопка «+ Добавить колонку» находится под экспериментом.

**Картинки.** Положить картинку в колонку можно любым способом:

- Ctrl+V с курсором в тексте колонки;
- перетаскиванием файла в область картинок;
- кнопками «Из устройства» и «Из буфера» (для кнопки «Из буфера» Chrome может спросить разрешение).

Картинки можно переставлять (↑ ↓) и удалять (✕). Клик по картинке увеличивает её, повторный клик закрывает. Удалённая картинка остаётся в папке `images/`.

**Текст.** Панель сверху: жирный, курсив, списки, нижний и верхний индексы (для P₂O₅ и подобного), заголовок. Текст из буфера вставляется без форматирования.

## Сохранность данных

- **Автосохранение** через 1,5 секунды после последней правки. Ctrl+S сохраняет сразу. Статус виден в верхней панели.
- Картинки записываются в `images/` в момент вставки.
- **Копии** кладутся в папку проекта `backups/`: при первом сохранении за сеанс и далее раз в 10 минут. Хранятся последние 20.
- Если запись на диск не удалась, программа показывает предупреждение и повторяет попытку каждые 5 секунд. Запасная копия лежит в браузере, и при следующем открытии программа предложит её восстановить.
- Закрыть вкладку с несохранёнными изменениями Chrome даст только после подтверждения.

## Структура проекта на диске

```
Мои журналы/
  Название-проекта/
    journal.html   ← готовый журнал; данные лежат внутри него
    images/        ← картинки
    backups/       ← автоматические копии
```

Папки проектов лежат вне репозитория. Редактор один, проектов может быть сколько угодно.

## Передать журнал коллеге

Заархивируйте папку проекта, коллега распакует её и откроет `journal.html`. Файл `journal.html` должен лежать рядом с папкой `images/`, иначе картинки не покажутся.

## Журналы старых форматов

Если в выбранной папке лежит журнал более раннего формата, он откроется и преобразуется автоматически. Перед записью программа сохраняет копию оригинала в `backups/`.

## Ограничения

- Только Chrome и Edge.
- Ctrl+Z отменяет набор текста, но не удаление блока или картинки. Для таких случаев есть копии в `backups/`.
- Картинки удалённых блоков остаются в `images/`.
- Фамилии и список присутствовавших свои у каждого проекта.

## Структура репозитория

```
index.html        редактор (открывать в браузере)
src/
  app.js          стартовый экран: открыть папку, создать журнал, преобразовать старый
  editor.js       редактор: блоки, колонки, картинки, диалог даты, автосохранение
  format.js       формат данных, даты, номера экспериментов, чтение journal.html
  view.js         сборка journal.html (страница для чтения и увеличение картинок)
  legacy.js       импорт журнала самого первого формата
  disk.js         работа с папкой проекта на диске
  style.css       стили приложения
examples/         место для демо-журнала
```

## Для разработчиков

Сборки нет: все скрипты подключены обычными тегами `<script>`, поэтому программа открывается двойным кликом без Node и Python. Общее пространство имён называется `LJ`.

Данные хранятся внутри `journal.html` блоком `<script type="application/json" id="lab-journal-data">`, а страница для чтения собирается из них:

```
{
  version: 2, title, subtitle,
  people: ["Иванов И.И.", ...],
  blocks: [
    { id, type: "experiment", date: "2026-10-27", attendees: [...],
      columns: [ { title, text: "<html>", images: [ { path: "images/..", caption } ] } ] },
    { id, type: "text", text: "<html>", images: [...] }
  ]
}
```

Номер эксперимента в данных не хранится, он считается заново при каждом показе. Журналы формата версии 1 приводятся к версии 2 при открытии (`LJ.migrate`).

Журналы пользователей не должны попадать в репозиторий: `.gitignore` исключает `journal.html`, `images/`, `backups/` и `my-journals/` в корне.
